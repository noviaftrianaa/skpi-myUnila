5. Penutup & Kontak

5.1 Catatan Kerahasiaan Kredensial

RAHASIA — TIDAK UNTUK DISEBARLUASKAN. Kredensial otentikasi (id_aplikasi, username, password, JWT token) yang diberikan oleh UPA TIK hanya boleh digunakan oleh PJ Aplikasi yang berwenang. Penggandaan, penyebaran, atau penggunaan oleh pihak yang tidak berwenang merupakan pelanggaran kebijakan keamanan informasi UPA TIK Universitas Lampung dan dapat berakibat pencabutan akses serta sanksi sesuai peraturan yang berlaku.

Praktik Keamanan yang Direkomendasikan

  • Jangan menyimpan password atau token di repositori Git, file log, atau frontend yang dapat diakses publik. Pakai environment variable atau secret manager (HashiCorp Vault, AWS Secrets Manager, dll.).
  • Rotasi password PJ secara berkala (rekomendasi: tiap 90 hari) atau saat ada indikasi kebocoran.
  • Selalu pakai HTTPS saat memanggil URL produksi. Hindari mendebug request di proxy publik (mis. webhook.site) yang akan menyimpan body request termasuk token.
  • Catat jti (JWT ID) token untuk keperluan audit. Server menyimpan log setiap akses melalui sistem logging terpusat.
  • Saat aplikasi konsumen di-decommission, kabari UPA TIK supaya akses di-non-aktifkan di sistem manajemen akses.

5.3 Request Endpoint, Pertanyaan, atau Masukan

Untuk permintaan endpoint baru, bug report, peningkatan kuota, atau pertanyaan teknis apa pun, kirim email ke:

📧 dev@unila.ac.id

Sertakan informasi berikut agar permintaan dapat diproses lebih cepat:

  • Nama aplikasi konsumen + id_aplikasi (kalau sudah punya)
  • Nama PJ Aplikasi + username
  • Endpoint yang dimaksud (METHOD + PATH + grup)
  • Tujuan penggunaan (mis. import data wisuda untuk SIAK)
  • Estimasi volume request per hari (untuk planning kapasitas)
  • Untuk bug report: ID request (header X-Request-ID) + timestamp + payload reproduksi
