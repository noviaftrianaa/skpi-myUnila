2. Cara Mendapatkan & Memakai Token

Seluruh endpoint /v1/* kecuali /v1/auth/* dan /v1/dashboard/ktw/* (publik) memerlukan JWT Bearer Token yang valid. Token didapatkan dari endpoint login dan harus disertakan pada setiap request melalui header Authorization.

2.1 Alur Otentikasi

Persiapkan kredensial

Anda butuh tiga komponen:

  • id_aplikasi — UUID aplikasi (dari tim UPA TIK)
  • username — username PJ Aplikasi (mis. app_pj)
  • password — password PJ Aplikasi

Kirim request login

POST ke endpoint /v1/auth/login dengan body JSON:

POST /v1/auth/login
Content-Type: application/json

{
  "id_aplikasi": "00000000-1111-2222-3333-444444444444",
  "username": "app_pj",
  "password": "RahasiaKuat!2026"
}

Simpan access_token dari response

Server merespons dengan token JWT yang berlaku selama 1 jam (3600 detik):

{
  "success": true,
  "message": "Berhasil Otentikasi",
  "data": {
    "token_status": "Baru",
    "token_dibuat": "2026-04-25 15:00:00",
    "token_kadarluwasa": "2026-04-25 16:00:00",
    "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "token_type": "Bearer",
    "expires_in": 3600
  },
  "timestamp": "2026-04-25T15:00:00+07:00"
}

Simpan nilai access_token untuk digunakan pada request selanjutnya.

Gunakan token di header request

Tambahkan header Authorization: Bearer <access_token>:

GET /v1/referensi/agama
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

Refresh saat token kedaluwarsa

Jika token sudah expired (atau hampir expired), ulangi langkah 2 untuk login kembali. Saat ini layanan tidak menyediakan endpoint refresh-token — gunakan login ulang sebagai mekanisme perpanjangan.

2.2 Memeriksa Validitas Token

Konsumen dapat memverifikasi token sebelum dipakai (mis. setelah lama idle) menggunakan endpoint /v1/auth/check-token. Berguna untuk menentukan apakah perlu login ulang atau token masih sah. 

POST /v1/auth/check-token
Content-Type: application/json

{
  "token_bearer": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}

Response sukses:

{
  "success": true,
  "message": "Token valid",
  "data": {
    "token_status": "Aktif",
    "token_dibuat": "2026-04-25 15:00:00",
    "token_kadarluwasa": "2026-04-25 16:00:00",
    "user": {
      "id_pengguna": "99999999-8888-7777-6666-555555555555",
      "username": "app_pj",
      "email": "pj.aplikasi@example.com",
      "nm_pengguna": "Nama Penanggung Jawab",
      "id_aplikasi": "00000000-1111-2222-3333-444444444444"
    }
  },
  "timestamp": "2026-04-25T15:30:00+07:00"
}

2.3 Memakai Bearer Token di Header

Setiap permintaan ke endpoint protected harus mencantumkan header berikut: 

Authorization: Bearer <access_token>

Contoh dengan curl:

curl -X GET "https://my.unila.ac.id/api-service/v1/referensi/agama" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." \
  -H "Accept: application/json"

Contoh dengan JavaScript (fetch):

const response = await fetch(
  "https://my.unila.ac.id/api-service/v1/referensi/agama",
  {
    headers: {
      "Authorization": `Bearer ${accessToken}`,
      "Accept": "application/json",
    },
  }
);
const data = await response.json();

Contoh dengan PHP (cURL):

$ch = curl_init("https://my.unila.ac.id/api-service/v1/referensi/agama");
curl_setopt_array($ch, [
    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_HTTPHEADER => [
        "Authorization: Bearer " . $accessToken,
        "Accept: application/json",
    ],
]);
$response = json_decode(curl_exec($ch), true);
curl_close($ch);

2.4 Penanganan Error Otentikasi

HTTPKondisiPesan tipikalTindakan
400 Validasi field VALIDATION_ERROR — id_aplikasi/username/password kosong/format salah Lengkapi/perbaiki field
401 Token tidak ada/invalid Authentication token not provided / Invalid token Login ulang untuk dapat token baru
403 Aplikasi tidak terdaftar Gagal Otentikasi. Aplikasi tidak terdaftar Pastikan id_aplikasi benar & aktif
403 Tidak punya peran Developer Akun tidak memiliki peran Developer Hubungi UPA TIK untuk pemberian peran 107
403 Endpoint tidak diotorisasi Access denied. user tidak punya otorisasi untuk <METHOD> <PATH> Minta UPA TIK menambah grant endpoint
429 Rate limit API rate limit exceeded Tunggu & turunkan kecepatan request (default 60/menit/IP)
Penting: jangan menyimpan token di tempat publik (mis. log file, repo Git, frontend statis). Token JWT memberi akses langsung ke data — perlakukan seperti password. Gunakan environment variable atau secret manager.
