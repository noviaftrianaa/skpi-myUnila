3. Format Standar Request & Response

3.1 Format Response Sukses

Seluruh endpoint mengembalikan struktur standar berikut saat sukses:

{
  "success": true,
  "message": "Berhasil mengambil data agama",
  "data": [ ... ],
  "meta": {
    "page": 1,
    "limit": 20,
    "total": 8,
    "total_pages": 1
  },
  "timestamp": "2026-04-25T15:00:00+07:00"
}
FieldTipeDeskripsi
successbooleanSelalu true untuk respon sukses
messagestringPesan deskriptif (Bahasa Indonesia)
dataarray / object / nullPayload aktual — array untuk list, object untuk detail
metaobject (opsional)Metadata pagination, hanya muncul pada endpoint list
timestampstring (ISO 8601)Waktu server saat respon dibuat (zona Asia/Jakarta)

3.2 Format Response Error

{
  "success": false,
  "message": "Validation failed",
  "error": {
    "code": "VALIDATION_ERROR",
    "details": {
      "id_aplikasi": "ID Aplikasi harus diisi",
      "username": "Username harus diisi"
    }
  },
  "timestamp": "2026-04-25T15:00:00+07:00"
}
FieldDeskripsi
successSelalu false
messageRingkasan error (manusiawi)
error.codeKode error mesin (lihat tabel di bawah)
error.detailsField-level errors (opsional, hanya untuk validation)

Kode Error Standar

CodeHTTPArti
VALIDATION_ERROR400Field input tidak valid
UNAUTHORIZED401Token tidak ada/expired/invalid
FORBIDDEN403Tidak punya hak akses (peran/grant kurang)
NOT_FOUND404Resource yang diminta tidak ditemukan
CONFLICT409Data sudah ada (duplikat unique)
RATE_LIMIT429Terlalu banyak request (60/menit/IP)
INTERNAL_ERROR500Kesalahan server, hubungi tim

3.3 Konvensi Pagination & Filter

Endpoint list mendukung query parameter standar untuk pagination, filter, dan sorting:

ParamTipeDefaultDeskripsi
pageinteger1Halaman ke- (mulai 1)
limitinteger20Jumlah baris per halaman (max 100)
searchstring-Pencarian di kolom-kolom umum (LIKE)
sort_bystringvariesNama kolom untuk pengurutan
sort_orderstringdescasc atau desc

Contoh: ambil halaman 2 (limit 50) dari list mahasiswa, urutkan nama A→Z:

GET /v1/mahasiswa/list_mahasiswa?page=2&limit=50&sort_by=nm_pd&sort_order=asc

Filter Khusus per Endpoint

Selain param standar, banyak endpoint punya filter spesifik (mis. id_sms, angkatan, tahun_ajaran). Lihat dokumentasi tiap endpoint pada Bab 4 untuk daftar lengkap.
