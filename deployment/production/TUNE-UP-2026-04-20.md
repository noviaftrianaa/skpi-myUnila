# Tune-up VM1 + VM2 + VM3 — 2026-04-20

Konteks: VM3 mengalami OOM kill masal 2026-04-19 (postgres/dockerd/containerd-shim/dbus killed → VM unreachable). Audit menunjukkan memory limit over-allocated di ketiga VM produksi. Tune-up ini fix limit supaya fit di VM 16GB RAM dan tambah GOMEMLIMIT untuk Go services supaya runtime aware limit container.

## Ringkasan perubahan

| Service | Sebelum | Sesudah |
|---|---|---|

### VM3 (7 Go services — PENTING karena VM3 yang OOM)

| Service | Sebelum | Sesudah | Tambah env |
|---|---|---|---|
| feeder | 8C / 12G | 4C / 4G | GOGC=75, GOMEMLIMIT=3750MiB |
| sister | 8C / 12G | 4C / 4G | GOGC=75, GOMEMLIMIT=3750MiB |
| monitoring | 4C / 4G | 2C / 2G + CRAWLER_CONCURRENT=2 | GOMEMLIMIT=1800MiB |
| keuangan | 2C / 2G | 2C / 1G | GOMAXPROCS=2, GOGC=100, GOMEMLIMIT=900MiB |
| myunila | 2C / 2G | 2C / 1G | GOMAXPROCS=2, GOGC=100, GOMEMLIMIT=900MiB |
| api | **NONE** | 2C / 1G | GOMAXPROCS=2, GOGC=100, GOMEMLIMIT=900MiB |
| project | 1C / 512M | 1C / 512M | GOMAXPROCS=1, GOGC=100, GOMEMLIMIT=450MiB |

VM3 total memory limit: **32.5G+ (over 16G VM) → 13.5G (safe)**

Semua service tambah `deploy.restart_policy`: on-failure, delay 10s, max_attempts 5, window 120s.

## Cara eksekusi (per VM)

Semua perintah di bawah dijalankan via SSH ke VM target. Urutan: VM3 dulu (paling kritis), lalu VM2, lalu VM1.

**IMPORTANT:** Selalu `docker compose ... pull` sebelum `up` bisa dilewati karena kita pakai local build. Gunakan `up -d --force-recreate` supaya container ambil env vars baru.

## Catatan

- Tune-up ini **tidak merebuild Docker image** kecuali Dockerfile berubah (dan Dockerfile tidak berubah di commit ini). `--force-recreate` cukup untuk apply env + resource changes.
- Downtime per service: ~10-30 detik saat recreate.
- Kalau service dependency ada (misal nginx depends pada auth/dashboard/public), recreate in order dari bottom-up.
- Health endpoint di tiap service sudah ada — kalau setelah restart ga healthy dalam 60 detik, cek `docker logs <container> --tail 50`.
